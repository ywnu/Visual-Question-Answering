# أسيل — إعداد البيانات وتحليلها (Data Preparation & EDA)

## المطلوب منك
تكمّلين التحليل السابق الموجود في `main.py`، **ولا تعيدين الشغل المنجز من الصفر**. اكتبي ملفًا مستقلًا مثل `src/data_preparation.py` يربط اسم كل صورة بسؤالها وإجابات الأشخاص عنها، مع الاحتفاظ بحقل `answerable`. افحصي الصور المفقودة أو التالفة، وحددي قاعدة واضحة لاختيار الإجابة المستهدفة للتدريب، مع الحفاظ على **جميع الإجابات المرجعية** للتقييم. افصلي بيانات التدريب عن الـValidation لتجنّب تسرب البيانات، واختبري عدة أمثلة واعرضي الأعداد النهائية.

## البيانات المطلوبة
من [موقع VizWiz الرسمي](https://vizwiz.org/tasks-and-datasets/vqa/): `train.json` و`val.json` وصور Training وصور Validation. الأعمدة الأساسية: `image`, `question`, `answers`, `answer_type`, `answerable`. احتفظي بالصور على جهازك أو هاردسك خارجي، **ولا ترفعينها على GitHub**. خلي مسارات الصور قابلة للتعديل لكل جهاز بدل كتابة مسار `D:` ثابت.

## التنسيق مع جمانه
اتفقي معها على مخرجات تجهيز البيانات: `image_path` و`question` و`reference_answers` و`target_answer` و`answerable`، ووضحي الحالات المستبعدة أو الغامضة.

## التسليم المطلوب
كود قراءة وتجهيز قابل لإعادة الاستخدام، طريقة تشغيل واضحة، تقرير بعدد العينات والمفقود والتالف، وعرض عينة تربط الصور بالأسئلة والإجابات. يعتبر الجزء مكتملًا عندما تستطيع جمانه تحميل البيانات على جهازها بمسارات صورها، دون تعديل `main.py`.

## معلومات مشتركة عن المشروع
المشروع عبارة عن موقع فعّال لمساعدة المكفوفين وضعاف البصر: يرفع المستخدم **صورة** ويكتب **سؤالًا**، فيُرجع نموذج VQA **إجابة نصية فعلية**. نموذج Logistic Regression الموجود في `main.py` يصنّف قابلية الإجابة فقط، وليس النموذج النهائي.

**الفريق:** أسيل (البيانات)، جمانه (نموذج VQA)، ديم (التدريب والتقييم)، حنان (الخلفية والربط)، بيادر (الواجهة وإمكانية الوصول).

**طريقة العمل:** كل بنت تشتغل على Branch المخصص لها وتفتح Pull Request للمراجعة قبل الدمج في `main`. لا ترفعن الصور الكبيرة أو ملفات ZIP أو أوزان النماذج أو المفاتيح السرية أو مجلد `.venv` إلى GitHub. لا تعدّلن `main.py` القديم بدون اتفاق.
