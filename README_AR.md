# حنان — تطوير الخلفية والربط (Backend & Integration)

## المطلوب منك
بناء Backend بلغة Python باستخدام Flask (أو إطار آخر بعد اتفاق الفريق) ليستقبل صورة وسؤالًا ويعيد **إجابة نموذج VQA الحقيقي**. تقدرين تبدئين بإجابة تجريبية واضحة أنها Mock إلى أن يصبح نموذج جمانه جاهزًا، لكن يجب استبدالها بالنموذج الفعلي قبل التسليم.

## اتفاقية API المبدئية — لم تُنفّذ بعد
- `GET /api/health` يعيد `{"status":"ok"}`.
- `POST /api/answer` يستقبل `multipart/form-data`: صورة بحقل `image` وسؤالًا نصيًا بحقل `question`.
- النجاح: `{"answer":"..."}`.
- طلب ناقص أو غير صالح: HTTP 400 و`{"error":"..."}`، والخطأ الداخلي برمز HTTP مناسب دون كشف تفاصيل حساسة.

## البيانات والأدوات المطلوبة
تحتاجين Flask وPillow وصورة اختبار صغيرة، ثم دالة جمانه `answer_question(image, question)`. **لا تحتاجين لتحميل مجموعة VizWiz كاملة** من أجل تطوير الـAPI. افحصي نوع الصور وحجمها، والأخطاء المتوقعة، واحرصي على تحميل النموذج مرة واحدة قدر الإمكان. لا تحفظي أسرارًا داخل الكود.

## التسليم المطلوب
ملفات `backend/`، طريقة التشغيل، أمثلة الطلب والاستجابة، اختبارات للحالات الناجحة والخاطئة، وربط فعلي مع نموذج جمانه. الاستضافة تعتبر مكتملة فقط بعد اختبارها بالفعل.

## معلومات مشتركة عن المشروع
المشروع عبارة عن موقع فعّال لمساعدة المكفوفين وضعاف البصر: يرفع المستخدم **صورة** ويكتب **سؤالًا**، فيُرجع نموذج VQA **إجابة نصية فعلية**. نموذج Logistic Regression الموجود في `main.py` يصنّف قابلية الإجابة فقط، وليس النموذج النهائي.

**الفريق:** أسيل (البيانات)، جمانه (نموذج VQA)، ديم (التدريب والتقييم)، حنان (الخلفية والربط)، بيادر (الواجهة وإمكانية الوصول).

**طريقة العمل:** كل بنت تشتغل على Branch المخصص لها وتفتح Pull Request للمراجعة قبل الدمج في `main`. لا ترفعن الصور الكبيرة أو ملفات ZIP أو أوزان النماذج أو المفاتيح السرية أو مجلد `.venv` إلى GitHub. لا تعدّلن `main.py` القديم بدون اتفاق.
